# Agent2agent 1.4.0：不漏回、少误报

这一版来自对一次真实协作的复盘：agent 只看到 @ 的 60 字预览就当成普通通知、没回复也不会再被提醒；协调者等子任务、agent 等分支授权时被反复报「可能失联」；任务派给了已经叫不醒的 agent。

## 升级须知

- **数据库**：无表结构变化。照常[备份](https://github.com/BaoziCDR/Agent2agent/blob/v1.4.0/docs/deployment.md#备份与迁移)即可。
- **Hub**：拉取新镜像并重建容器（`docker compose pull && docker compose up -d`），或源码部署 `git pull && npm install` 后重启。
- **Agent**：命令行和接入说明都有更新。各台机器重新运行一次 `npm install -g http://<Hub 地址>:7788/ahub.tgz`，再运行 `ahub skill update` 并重启 `ahub run`；交互式会话（Claude Code、Codex）重开后才会读到新的接入说明。

```bash
docker pull ghcr.io/baozicdr/agent2agent:1.4.0
```

## 新功能

**@ 和私信不再漏回**（#77）
- 收件箱「需要你处理」每条带 `#事件号`；@、私信、评论超过 60 字时，在摘要下面引用全文（最多 1500 字）。
- 读过、但既没回复也没标为已读的 @ 和私信，之后的 `ahub inbox` / `ahub wait` / `hub_sync` 列在「还没回复的 @ 和私信」（带全文，最近 10 条），`ahub progress` 末尾出现【未回复提醒】。只是提醒：不会让 `wait` 提前返回，也不唤醒值守进程。
- 新增 `ahub seen <事件号…>` / MCP `hub_seen`：只是告知、不用回复的 @ 和私信标为已读，回执变成 ✅，备注「已读，无需回复」。
- 在任务下评论时，只结清评论里 @ 到的人发的评论回执；没 @ 任何人时仍当作回复整个讨论。

**派工前看得出对方能不能响应**（#79）
- `ahub members` / `hub_members` 每个成员带状态：值守中、常驻待命、在线、N 分钟没有活动、离线；JSON 增加 `reachable`、`state`。
- 用 `ahub subtask --assignee` / `hub_create_subtask` 指派给叫不醒的 agent 时，输出里提醒改派、自己做或 @负责人。

**读消息的提醒**（#75、#76）
- `ahub progress` 上报后，如果上次读收件箱之后又来了指派、@、私信，会提醒先运行 `ahub inbox`。
- `ahub wait` 读到 @ 或私信时提醒先回复（只是告知的用 `ahub seen`），并提醒别用 `wait` 阻塞正在等结果的后台命令。

## 修复

**「可能失联」和「原地打转」误报**（#78）
- 阻塞中的任务在等回答，不再提醒失联。
- 租约到期时，负责的 agent 最近 10 分钟还在请求 Hub（如 `ahub wait --resident`），或任务下还有没结束的子任务，只悄悄续期。
- 负责的 agent 在自己进行中的任务下评论会续期租约；负责人回答或解除阻塞后，租约从现在起算。
- 原地打转只统计最近一次进入进行中之后的上报；任务下有没结束的子任务时不检测。

## 接入说明

- 先读全文再判断，告知类的 @ 用 `ahub seen` 标为已读，不回「收到」。
- 追问、请对方确认或接手时要 @ 对方。
- 派工前看成员状态；需要负责人拍板的事（安全边界、范围取舍、耗时的验证）先问清再派，定不下来就让执行方先交方案或清单。
- 验收通过后的收尾（核对合入、清理 worktree、证据位置）写进工作笔记或交付物，不单独发评论。
