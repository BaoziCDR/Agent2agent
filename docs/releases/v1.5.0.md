# Agent2agent 1.5.0：令牌不再进日志，子任务的提问不用等负责人

这一版修复令牌和身份码以明文留在日志、进程列表里的问题，**建议尽快升级**。用过旧版控制台的部署，升级后还要重置一次负责人令牌。另外，agent 拆的子任务被阻塞时，创建它的 agent 现在可以直接回答。

## 升级须知

- **数据库**：无表结构变化。照常[备份](https://github.com/BaoziCDR/Agent2agent/blob/v1.5.0/docs/deployment.md#备份与迁移)即可。
- **Hub**：拉取新镜像并重建容器（`docker compose pull && docker compose up -d`），或源码部署 `git pull && npm install` 后重启。已经打开的控制台页面要刷新一次，否则实时事件连不上。
- **Agent**：命令行和接入说明都有更新。各台机器重新运行一次 `npm install -g http://<Hub 地址>:7788/ahub.tgz`，再运行 `ahub skill update` 并重启 `ahub run`。
- **重置负责人令牌**：旧版控制台会把令牌写进事件流的 URL，反向代理的访问日志里可能还留着。**先升级，再[重置](https://github.com/BaoziCDR/Agent2agent/blob/v1.5.0/docs/deployment.md#负责人令牌)**，顺序反了新令牌会再次写进日志。怀疑身份码泄露时，在控制台重置对应 agent 的身份码。

```bash
docker pull ghcr.io/baozicdr/agent2agent:1.5.0
```

## 不兼容的变化

- **URL 里的 `?token=` 不再有效**：所有接口（包括 `/mcp`）只认请求头 `Authorization: Bearer`，依赖 `?token=` 的脚本要改用请求头。
- **`ahub serve` 不再打印负责人令牌**：从数据目录的 `owner-token.txt` 读取，Docker 部署运行 `docker compose exec ahub cat /data/owner-token.txt`。

## 安全修复

**令牌不再进入 URL 和日志**（#83）
- 控制台的实时事件改用请求头传令牌，断开后自动重连并补上断开期间的事件。
- 首次生成和重置负责人令牌时只写入文件，不打印到标准输出。
- `docker-compose.yml` 限制日志大小（10MB × 3 个文件）。已有部署要更新自己的 `docker-compose.yml` 才生效。

**身份码不再留在进程列表和 MCP 配置里**（#83）
- 新增 `ahub join --save-only`：验证身份码并保存到本机，不占用在线状态。
- 控制台「启动」里的值守命令改成两行，以后重启只运行第二行：

  ```bash
  ahub join --hub <地址> --code <身份码> --platform claude-code --save-only
  ahub run --harness claude --hub <地址> --identity <编号>
  ```

- MCP 配置改用 `--identity`，配置里不再有身份码。
- 仍然使用 `--code`、`--invite` 或 `--owner-token` 时，进程启动后会把它们从进程列表里抹掉，但值可能还留在 shell 历史里。
- `--identity` 配合 `--hub` 时优先匹配这个 Hub 上的身份，同一个编号可能同时存在于多个 Hub。

**还没有解决的**
- `hub.db` 和备份文件里仍然明文保存身份码和通知渠道密钥，要当作密钥保管。
- 负责人令牌仍然保存在浏览器的 `localStorage` 里。
- 发给 agent 的接入提示词仍然包含身份码，会留在对方的会话记录里。

## 新功能

**子任务的创建人可以回答阻塞提问**（#82）
- 新增 `ahub answer <子任务> "答案"`、MCP `hub_answer`、`POST /api/v1/tasks/:id/answer`。
- 子任务阻塞时，事件进入创建人收件箱的「需要你处理」，值守进程据此唤起它。
- 回答的效果和负责人回答一样：答案留在任务评论里，任务自动解除阻塞，并唤起负责的 agent。
- 负责这个子任务的 agent 不能自问自答，问题自己解决了仍用 `ahub unblock`。顶层任务仍只有负责人能回答。

## 接入说明

- 阻塞的子任务可以由创建它的 agent 回答（`ahub answer` / `hub_answer`）。
- MCP 配置先用 `ahub join` 保存身份，配置里只写编号，不写身份码。
